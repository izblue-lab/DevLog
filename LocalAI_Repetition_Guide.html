로컬 AI 문장 반복 루프
근본 해결 가이드

30B 이상 대형 모델에서 생기는 '도돌이표 무한 반복' 원인과 4가지 근본 해결책

핵심 요약 (한 줄 결론)

검수 게이트(Guardrail)는 사후에 불량 텍스트를 걸러내는 '최후의 안전망'일 뿐입니다.
샘플링 파라미터(repeat_penalty) 최적화와 프롬프트 단계 분할(Chunking)만 적용해도 루프의 95% 이상을 사전 차단할 수 있습니다.

1. 왜 로컬 AI가 같은 문장을 계속 반복할까요?

AI가 문장 중간에 갇혀 도돌이표를 도는 이유를 직관적으로 이해해 봅니다.

🚗
"도돌이표 내비게이션" 비유로 이해하기
AI가 글을 쓰는 과정은 내비게이션이 앞길을 예측하며 길을 찾는 것과 같습니다.
1. AI는 자기가 방금 쓴 단어들을 보면서 다음에 올 가장 어울리는 단어를 확률적으로 고릅니다.
2. 그런데 글이 길어지거나 특정 단어가 한 번 반복되면, AI 두뇌가 "어? 방금 이 단어를 썼으니 또 쓰는 게 가장 자연스럽겠네!"라는 착각(자기 강화 피드백)에 빠집니다.
3. 결국 로터리에서 빠져나오지 못하고 계속 같은 자리만 빙빙 도는 '도돌이표 무한 루프'에 갇히게 됩니다.

2. 반복 루프를 뿌리 뽑는 4가지 근본 해결책

게이트 없이도 결과물을 무결점으로 만드는 4단계 사전 방어선입니다.

1
가장 즉각적 효과
샘플링 파라미터 최적화
repeat_penalty를 1.15~1.25로 상향하고, 감시 범위인 repeat_last_n을 128로 넓혀 방금 쓴 단어에 확률적 벌점을 부여합니다.
2
신경망 왜곡 방지
양자화 품질 확보
VRAM을 아끼려고 Q2, Q3 등 과도한 저비트 압축 모델을 쓰면 주의집중 가중치가 왜곡됩니다. 최소 Q4_K_M 또는 Q5_K_M을 권장합니다.
3
챕터별 글쓰기
프롬프트 단계 분할 (Chunking)
2,000자 장문을 단숨에 뽑지 않고, [1단계 개요/목차 ➔ 2단계 섹션별 본문 ➔ 3단계 결론]처럼 단계별로 쪼개어 호출해 컨텍스트 오염을 차단합니다.
4
물리적 강제 차단
Stop Sequence 등록
할 말이 다 끝났는데도 AI가 헛돌지 않도록, stop: ["###END###", "\n\n\n\n"]를 등록해 글이 끝나는 즉시 물리적으로 연산을 중단시킵니다.

3. 바로 복사해서 쓰는 Ollama 파라미터 최적 옵션

Ollama API 호출 시 options 필드에 그대로 복사하여 전달하세요.

JSON / Ollama API Request 
{
  "model": "qwen2.5:32b", // 또는 사용하는 30B/8B 모델명
  "messages": [
    { "role": "system", "content": "You are a concise expert." },
    { "role": "user", "content": "본문 작성 요청 프롬프트..." }
  ],
  "options": {
    "temperature": 0.65,      // 0.65 유지 (너무 낮으면 반복에 취약)
    "repeat_penalty": 1.18,   // 1.15 ~ 1.25 추천 (반복 단어 확률 벌점)
    "repeat_last_n": 128,     // 최근 128단어를 기억하며 중복 감시
    "top_p": 0.9,             // 상위 90% 확률 분포 내 샘플링
    "stop": [                 // 할 말 끝났을 때 즉시 종료 마커
      "###END###",
      "\n\n\n\n",
      "========================="
    ]
  }
}

4. 검수 게이트(Validation Gate) 4대 설계 원칙

품질은 엄격하게 잡고, 허용 오차(Tolerance)는 유연하게 두는 실무 원칙입니다.

1. 중복 문장 감지 & 자동 정제
동일한 문장이나 표현이 2회 이상 연속으로 감지되면 중복 구간을 잘라내거나(Truncate) 1개만 남겨 깔끔하게 마감합니다.
2. 분량 상한선 감시 (Overflow Gate)
서비스 레이아웃을 깨뜨릴 수 있는 비정상적인 장문이나 성의 없는 단문을 감지하여 목표 분량 범위를 안정적으로 유지합니다.
3. 목표 개수 ±1개 유연한 허용 (Tolerance)
N개의 항목/단락을 요청했을 때 기계적으로 탈락시키지 않고, 문맥상 완성도가 높다면 ±1개의 오차는 자연스러운 흐름으로 인정합니다.
4. 포맷 & 특수문자 찌꺼기 정제
AI가 출력한 마크다운 백틱(```), 이스케이프 문자, 깨진 태그 등 UI 가독성을 해치는 노이즈를 렌더링 전에 자동으로 세척합니다.

5. 한눈에 보는 비유 요약 표

핵심 파라미터와 기법의 일상 비유 매핑입니다.

항목 / 파라미터 권장 설정값 비유적 쉬운 설명
repeat_penalty 1.18 (1.15~1.25) "방금 한 말 또 하면 벌점 주기"
repeat_last_n 128 토큰 "최근 128단어 기억하며 중복 감시하기"
temperature 0.65 "적당한 창의성과 표현의 유연함 열어두기"
stop ["###END###"] "할 말 다 끝났으면 바로 펜 내려놓기"
Chunking (단계분할) 목차/챕터별 분할 "책 한 권을 챕터별로 나누어 쓰기"
검수 게이트 유연한 허용 (Tolerance) "사후 품질을 든든하게 받쳐주는 안전 그물망"

자주 묻는 질문 (FAQ)

로컬 모델 구동 중 겪는 문제에 대한 추가 가이드입니다.

30B 이상 대형 모델을 로컬 환경(4-bit Q4_K_M 등)에서 돌릴 때 VRAM 한계로 낮은 Temperature(0.1 이하)를 사용하거나 양자화 압축으로 인해 주의집중(Attention) 가중치 손실이 생길 때 특정 토큰 선택 확률이 한쪽으로 극단적으로 쏠리기 때문입니다.
e4b 등 소형 모델은 포스트 분량이 짧으면 문장 반복은 적지만, 글자 수 제한 초과나 포스트 개수 누락 같은 '규칙 이탈'이 더 잦습니다. 따라서 파라미터 벌점과 함께 분량/포맷 검수 게이트를 함께 두는 것이 가장 안전합니다.
한 번의 프롬프트에서 너무 많은 분량을 요구하고 있는지 점검해 보세요. 프롬프트를 [목차 생성 ➔ 섹션별 분할 호출] 형태로 쪼개면(Chunking) 모델이 기억해야 할 문맥이 줄어들어 루프가 즉각 해결됩니다.
